# greenline

[English version](README.md)

Тюнинг NVIDIA GPU под Windows через официальный NVML и приватные функции NVAPI, без сторонних зависимостей:

- потолок частоты ядра;
- offset частоты ядра и памяти;
- поточечная VF-кривая с полкой по напряжению (андервольт);
- проверка стабильности каждой точки кривой: самопроверяющееся CUDA-ядро (через `nvcuda.dll`, PTX компилирует драйвер,
  CUDA SDK не нужен).

Работает только с GPU 0. Все изменения живут до перезагрузки или сброса драйвера, в GPU и драйвере ничего не сохраняется.

| Проект | Что |
|---|---|
| `Greenline.Core/` | библиотека (`net8.0-windows`, namespace `Greenline`): `Gpu` (NVML/NVAPI), `GpuStress` (стресс-тест на CUDA), `GpuCli` (командная строка, можно встроить в другое приложение) |
| `greenline-cli/` | `greenline.exe`, тонкая обёртка над `GpuCli.Run` |

## Требования

- Windows 10/11 x64, NVIDIA GPU со свежим драйвером (`nvmlDeviceSetClockOffsets` появился в R555; проверено на 616.56).
- Чтение работает от любого пользователя, любая запись требует терминала с правами администратора.
- Сборка: .NET 8 SDK. Запуск: .NET 8 Runtime.
- Проверено на GeForce RTX 4050 Laptop GPU. Другие GPU должны работать, но раскладку VF-кривой и диапазоны offset'ов
  сообщает драйвер, и они могут отличаться.
- Другие тюнеры (MSI Afterburner, UXTU и подобные) пишут те же настройки и перезаписывают друг друга: запускайте что-то одно.

## Сборка

```
dotnet build greenline-cli -c Release
greenline-cli\bin\Release\net8.0-windows\greenline.exe help
```

## Использование

```
greenline                                        статус: частоты и offset'ы
greenline curve                                  VF-кривая: напряжение -> частота и offset точки
greenline clock 2100                             потолок частоты ядра 2100 МГц (0 = снять)
greenline offset 150 1000                        ядро +150 МГц, память +1000 МГц (сдвиг всей кривой)
greenline curve set 700:+300 850:+250 cap 900    поточечные offset'ы, полка выше 900 мВ (андервольт)
greenline curve reset                            все offset'ы точек обратно в 0
greenline stress 700-900 30                      проверить каждую точку кривой от 700 до 900 мВ, по 30 с
```

Запись спрашивает подтверждение, `--yes` (`-y`) его пропускает. Пример вывода:

```
> greenline
NVIDIA GeForce RTX 4050 Laptop GPU: core 210 MHz (max 3105), memory 810 MHz (max 8001)
Offsets: core 0 MHz (-1000..1000), memory +1200 MHz (-1000..3000)
```

### VF-кривая

`curve set` принимает якоря `<мВ>:<offset МГц>`: между якорями offset интерполируется по напряжению, за их пределами
держится постоянным. `cap <мВ>` делает кривую плоской выше этого напряжения на частоте, которую она там достигает, поэтому
GPU не поднимается выше этого напряжения. `offset` переписывает все точки одним значением и стирает поточечную кривую.

### Стресс-тест

`stress [<мВ>-<мВ>] [<секунды>] [<шаг мВ>]` фиксирует частоту ядра на каждой точке кривой в диапазоне (по умолчанию
600 мВ..верх, шаг 50 мВ, по 30 с) и гоняет CUDA-ядро, каждый результат которого побитово сравнивается с эталоном,
посчитанным на CPU, поэтому ловятся и тихие ошибки вычислений. Потолок частоты и VF-кривая восстанавливаются после теста,
в том числе после сброса драйвера. Markdown-отчёт дописывается в `gpu-stress.md` в текущей папке.

Чистые вычисления не нагружают RT-, тензорные и текстурные блоки, а лимит мощности не даёт верху кривой удержать
зафиксированную частоту: успешный прогон — хороший знак, но не гарантия. Окончательная проверка — реальная нагрузка.

## Использование библиотеки

Подключите `Greenline.Core/Greenline.Core.csproj` через `ProjectReference` или упакуйте в локальный NuGet-фид:

```
dotnet pack Greenline.Core -c Release -o <папка фида>
```

(`pack.ps1` делает это в `..\packages`.) При каждом изменении поднимайте `<Version>` в `Greenline.Core.csproj`: NuGet
кэширует версию навсегда. В пакет встроены pdb и исходники, так что отладчик может заходить в библиотеку.

Настройки хоста (статические, задать один раз при старте):

| Свойство | По умолчанию | Зачем |
|---|---|---|
| `GpuCli.Prog` | `greenline` | как команды пишутся в справке, подсказках и отчёте стресс-теста, например `myapp gpu` |
| `Gpu.StateDir` | `%ProgramData%\greenline` | `gpucurve.txt` / `gpucurve.sig`: последняя записанная кривая и её подпись (`Gpu.CurveIsLast`) |
| `GpuStress.ReportFile` | `gpu-stress.md` | markdown-отчёт каждого прогона (относительно текущей папки), `null` — не писать |

`GpuStress.BusyMutex` (`Global\greenline-stress`) держится, пока идёт стресс-тест: хост, который периодически заново
применяет свои настройки, в это время не должен трогать GPU. Для GUI — `GpuStress.Execute(request, ISink, CancellationToken)`.
